Overview			            *build.nvim* *build.nvim-overview*

A lua neovim plugin to extend the functionality of the `:compiler` and `:make`
workflow with more build systems and workspace autodetection.

REQUIREMENTS                                         *build.nvim-requirements*

- neovim >= 0.10

FEATURES                                                 *build.nvim-features*

Automatically detects your build system based on the first build file found,
currently supports:
- CMake (`CMakeLists.txt`)
- Cargo (`Cargo.toml`)
- Just (`Justfile`)
- Make (`Makefile`)
- Meson (`meson.build`)
- Ninja (`build.ninja`)
- Setuptools (`setup.py`)
- Zig (`build.zig`)

Automatically detects project root based on the presence of a file
- Git, mercurial, svn and a few other version control systems
- `package.json`

Gets out of your way
- Integrates with builtin neovim features to allow transparent overriding
- Sets up autocommands for correct behaviour by default

Installation                                         *build.nvim-installation*

Install as you would any other plugin.

VIM.PACK              *build.nvim-vim.pack* *build.nvim-installation-vim.pack*

>lua
	vim.pack.add({
		'https://github.com/cyuria/build.nvim'
	})

VIM-PLUG              *build.nvim-vim-plug* *build.nvim-installation-vim-plug*

>vim
	" Vimscript
	call plug#begin(s:plug_dir)
	Plug "cyuria/build.nvim"
	call plug#end()
<

LAZY.NVIM           *build.nvim-lazy.nvim* *build.nvim-installation-lazy.nvim*

>lua
	require('lazy').setup({
		"cyuria/build.nvim",
	})
<

PACKER                    *build.nvim-packer* *build.nvim-installation-packer*

>lua
	-- lua
	use {
		"cyuria/build.nvim",
	}
<

Usage                                                       *build.nvim-usage*

By default `build.nvim` automatically sets the compiler with `:compiler`,
which will itself set `'makeprg'` and `'errorformat'`. These work with `:make`
and the quickfix list.

By default this plugin is triggered on the `BufRead` and `DirChanged`
autocommands. This can be changed as follows:
>lua
	-- only update on BufWrite
	require('build').autocmds({ 'BufWrite' })

To unset all autocommands, simply pass an empty table.
>lua
	-- unset build.nvim autocommands
	require('build').autocmds({})

You can then set autocommands as you like. For example:
>lua
	vim.api.nvim_create_autocommand({ 'BufRead' }, {
		callback = function()
			require('build').search()
		end
	})

See also |build.nvim-configuration|

Some build systems, such as meson and cargo will need an extra argument to run
successfully. This is because the command line for those build systems doesn't
have a default execution target, so you will need to specify what operation to
run, such as `:make compile` with meson or `:make build` with cargo.

If you want to avoid this, use a `build.sh` script, see |build.nvim-build.sh|.

BUILD.SH                                                 *build.nvim-build.sh*

When `build.nvim` detects a `build.sh` file, the build system is set to
`build_sh`.

This build system supercedes all other build systems (is checked for first),
so it can be used to wrap another existing build system.

The script is called with all arguments passed through, so `:make` will simply
call the script with no arguments and `:make foo bar baz` will call `build.sh`
with the arguemnts `foo`, `bar` and `baz` in that order.

>vim
	:make
	:make foo
	:make test

CMAKE                                                       *build.nvim-cmake*

When `build.nvim` detects a `CMakeLists.txt` file, the build system is set to
CMake.

CMake requires extra arguments to be passed.

>vim
	:make -B build/
	:make --build build/

CARGO                                                       *build.nvim-cargo*

When `build.nvim` finds a `Cargo.toml` file, the build system is set to Cargo.

Cargo requires extra arguments to be passed.

>vim
	:make clean
	:make check
	:make build
	:make run
	:make add serde --features=derive

JUST                                                         *build.nvim-just*

When `build.nvim` finds a `justfile` (or `Justfile`), the build system is set
to Just.

Just may take extra arguments to specify a target recipe.

>vim
	:make
	:make -l
	:make build
	:make test

MAKE                                                         *build.nvim-make*

When `build.nvim` finds a `Makefile`, the build system is set to make. Make is
special as it is Vim's default compiler and target for `:make`.

Make may take extra arguemnts to specify a target.

>vim
	:make
	:make build
	:make clean
	:make build -j 8
	:make test

MESON                                                       *build.nvim-meson*

When `build.nvim` finds a `meson.build` file, the build system is set to
Meson.

Meson requires extra arguments to be passeed.

>vim
	:make setup build
	:make compile -C build

NINJA                                                       *build.nvim-ninja*

When `build.nvim` finds a `build.ninja` file, the build system is set to
Ninja.

Ninja is often used as a backend for meta build systems, so if your project
uses a build system not recognised by `build.nvim`, the compiler may be set to
Ninja.

Ninja may take extra arguments to specify an edge to build.

>vim
	:make
	:make test

NPM                                                           *build.nvim-npm`

When `build.nvim` finds a `package.json` file, the build system is set to NPM.

Often projects will contain a `package.json` file and not use NPM for
building, so NPM is deprioritised here.

NPM requires extra arguments to be passed, `makeprg` is set to `npm run $*`,
so you will usually want to call something like `:make build`.

>vim
	:make build
	:make test

SETUPTOOLS              *build.nvim-setuptools* *build.nvim-python-setuptools*

When `build.nvim` finds a `setup.py` file, the build system is set to
Setuptools.

>vim
	:make

ZIG                                                           *build.nvim-zig*

When `build.nvim` finds a `build.zig` file, the build system is set to Zig
(specifically `zig_build`, as bundled with NeoVim).

Zig may take extra arguments to specify which step to run.

>vim
	:make
	:make test
	:make run
	:make -Doptimize=ReleaseSmall

Configuration                                       *build.nvim-configuration*

Configure `build.nvim` by setting `vim.g.build_nvim_options` or by calling
`require('build').setup({...})`.

The `setup()` call is a simple wrapper that sets the global variable and
doesn't need to be called.

`build.nvim` comes with the following options and defaults.

>lua
	vim.g.build_nvim_options = {
		-- A list of marker files which indicate the parent directory
		-- should be considered the project root
		root = {
			".bzr",
			".git",
			".hg",
			".svn",
			"_darcs",
			"package.json",
		},

		-- A marker files and compiler/build system associations,
		-- sorted by priority
		compilers = {
			{
				["build.sh"] = "build_sh",
			},
			{
				["CMakeLists.txt"] = "cmake",
				["Cargo.toml"] = "cargo",
				["Justfile"] = "just",
				["build.zig"] = "zig",
				["justfile"] = "just",
				["meson.build"] = "meson",
				["setup.py"] = "setuptools",
			},
			{
				["Makefile"] = "make",
				["build.ninja"] = "ninja",
				["package.json"] = "npm",
			},
		},

		-- Deprecated
		update_events = nil,
		root_extra = nil,
		compilers_extra = nil,
	})
